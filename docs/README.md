# 文档地图

> 这是本仓库所有文档的**唯一入口**。新增/删除/改名文档必须同步更新本页。
> 当前版本：**16.1 / iLayoutSettings**（源码对应 16.1；`dist/` 仍保留 16.0 / 15.5 / 14.8 发布包，对应关系见 [状态](00-status.md)）。

## 一、按角色选路径

### 1. 只是想用（3 分钟）

```
README.md → 下载 dist/*.apk → docs/04-install.md
```

### 2. 想改代码（30 分钟）

```
docs/01-overview.md     项目边界：能改什么、不能改什么
docs/02-architecture.md Hook 链路 + 每个类的职责
docs/05-design-notes.md 为什么这样实现（方案取舍）
docs/06-pitfalls.md     动手前先看，能省掉一半调试
docs/03-build.md        构建三件套与签名
```

### 3. 新开一个 AI 会话（必读，5 分钟）

```
agent.md                       强制工作流：怎么接手、怎么写记录
docs/00-status.md              当前版本 / 已知问题 / 下一步
docs/sessions/README.md        最近几次会话的索引
docs/sessions/<最新>.md        上一次到底改了什么、踩了什么坑
```

读完这四份再动手。**不要凭记忆改代码**——历史上有多次「以为改回去了、其实没有」。

## 三、文档状态标记

正文开头统一用一行标记，避免「这份还准不准」的困惑：

- `状态：现行` —— 与当前源码一致，可直接照做；
- `状态：历史` —— 描述旧版本行为，只作考古；
- `状态：草稿` —— 未验证，别当结论。

`07-changelog.md` 是历史全文，天然属于「历史」。

## 四、维护规则（谁在什么时候改什么）

| 触发 | 必须更新的文档 |
| --- | --- |
| 每次会话结束 | `sessions/<新文件>.md` + `sessions/README.md` 索引 + `00-status.md` |
| 改了版本号 / 出了新 APK | `07-changelog.md` 顶部 + `00-status.md` + `README.md` 版本徽章 |
| 新增 Hook / 类 / 资源映射 | `02-architecture.md` |
| 踩到新坑或推翻旧结论 | `06-pitfalls.md`（旧结论不要删，标注「已过时」并写清原因） |
| 新增/改名/删除文档 | **本页** |
| 构建脚本或依赖升级 | `03-build.md` |

## 五、写作约定

1. **一页只回答一类问题**，不要把安装、原理、历史混在一份里；
2. 结论先行：每节第一段给结论，细节放后面；
3. 命令必须可直接复制执行，路径用占位符并说明（如 `<repo>`）；
4. 涉及「之前是错的」时，写清**错在哪、怎么发现的**，比只写正确做法更有价值；
5. 引用代码位置用 `文件:行` 或 `类#方法`，方便跳转。

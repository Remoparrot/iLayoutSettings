# 路线图与已知限制

> 状态：**现行** · 最后更新：2026-11-09

## 1. 已知限制（当前版本就有）

| 限制 | 影响 | 备注 |
| --- | --- | --- |
| 只适配澎湃 OS 3 设置的类名 | 换 ROM / 大版本可能部分失效 | 全部 `findClassIfExists` + 日志，不会崩 |
| 平板 / 分屏未适配 | 宽屏下卡片宽度、搜索栏位置可能不理想 | 没做 `sw600dp` 断点 |
| 首页映射靠资源 id 名 | 系统改 id 名后需要补 `SLOT_IDS` | 有标题兜底 |
| 无自动化测试 | 回归靠真机清单 | 见 [安装 · 检查清单](04-install.md#4-首次使用检查清单) |
| 源码与 14.8 发布包不一致 | 14.8 重编包签名不同，无法覆盖；15.0 起 `dist/` 与源码同源 | 见 [状态](00-status.md#已知问题) |
| 液态玻璃 / 开关 / 顶栏模糊已上机验证（15.3） | 仍缺：120Hz 慢动作、分屏/平板、深浅色中间帧、第三方主题图标包 | 2026-11-10 真机：主题飞行图标生效、搜索栏保留原生胶囊且浅色无阴影、顶栏滑杆 0→300 实时生效 |
| 无 CI | 发版靠本地构建 | 构建脚本已可参数化，适合接 Actions |

## 2. 待办（按优先级）

### P0 — 发版可信度

- [ ] **固定 keystore**，用同一把 key 重签并发布，确认能从 14.8 覆盖安装；
- [ ] 明确「发布包来自哪个 commit」，在 Release 说明里写 sha256 与构建命令；
- [ ] 清理 `Hook` 未引用的遗留类（`GlassToggle` / `IntroCard` / `AboutIos` / `AboutExtras` / `TitleFix` / `TitleOverlay` / `PrefsBridge`）与 `BottomSearch` 里的 lattice 反射分支；
- [ ] 清理后对比 dex 体积，确认与发布包量级一致。

### P1 — 质量与协作

- [ ] GitHub Actions：`tag push` 触发构建 + 上传 APK + 生成 Release（需要 android-36 platform 与 build-tools，可用 docker 镜像）；
- [ ] Issue 模板（bug / feature）+ 反馈清单（已有 [模板](08-troubleshooting.md#10-反馈模板)）；
- [ ] 真机回归清单固化成 `docs/04-install.md` 的 checklist（已有初版）；
- [ ] 平板适配：`sw600dp` 下搜索栏宽度上限、卡片左右留白。

### P2 — 能力

- [ ] 首页 slot 映射可配置（不改代码也能调整顺序）；
- [ ] 二级页图标继续扩充（覆盖更多设置页）；
- [ ] 从 15.x–17.x 实验分支回迁「玻璃参数可调」——14.9 已回迁液态玻璃本体与 `Prefs` 键，
      只剩 GUI 页（`MainActivity`）未做，**以独立分支/PR 形式**推进；
- [ ] 深色模式/主题切换后的自动重排（目前靠重进页面）。

## 3. 明确不做

- 自绘整个设置界面（违背「不重绘」原则，维护成本无上限）；
- 接管搜索逻辑；
- 搬 smali / 打包第三方反编译代码进 dex（15.x 已证明不可维护，见 [设计思路](05-design-notes.md) 2.6 节）；
- 支持非 MIUI/HyperOS 的 ROM。

## 4. 怎么提新需求

1. 先确认需求落在「重排 / 注入 / 显隐」范围内；
2. 在 Issue 里写清：目标页面、期望效果、参考图、机型与系统版本；
3. 实现后按 [agent.md](../agent.md) 记录设计取舍与踩坑。

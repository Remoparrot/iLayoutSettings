## 4. 设计思路

- **问题本质**：仓库状态（main = 15.5）与发布状态（Releases = v14.8）脱节，README 又按发布状态写，导致「文档说 14.8 是稳定版、代码已经是 15.5」。
- **方案对比**：
  - A 只发 v15.5 —— Release 页一眼看到当前版本，改动最小；缺点：14.9~15.4 没有独立 release（changelog 里有记录）。
  - B 补齐 14.9~15.5 —— 历史完整、每个版本都有下载；缺点：7 条公告刷屏，15.1 的 APK 已丢失，只能无附件，反而制造「这个版本没东西」的疑问。
  - C 只打 tag —— 零成本；缺点：Releases 页仍停在 14.8，等于没同步。
- **最终选择**：A（用户定）。取舍是「当前版本可下载」优先于「历史版本全可下载」，历史靠 `docs/07-changelog.md` 承担。

## 5. 踩过的坑

### 坑：给 GitHub API 发中文 JSON，`Invoke-RestMethod` 一直 422

- **现象**：`Invoke-RestMethod -Method Post -Body $bytes` 返回 422，错误信息里夹着 `"PSPath" => "D:\\Temp\\..."` 这种 PowerShell 对象转储。
- **根因**：`Get-Content -Raw` 拿到的内容被当成 PSObject 序列化进 `body` 字段，发出去的 JSON 不是合法字符串，GitHub 直接 422；换成 `-Body [byte[]]` 也没解决。
- **解法**：`[PSCustomObject]` + `ConvertTo-Json -Depth 5 -Compress` 写到 UTF-8 **无 BOM** 文件，再 `curl.exe --data-binary "@release.json"` 发（返回 201）。
- **如何避免**：长文本 / 中文的 GitHub API 调用一律「先落文件，再 curl」；不要在 `-Body` 里直接塞多行字符串。

### 坑：这台机器的 PowerShell 里没有 `JavaScriptSerializer`

- **现象**：`New-Object System.Web.Script.Serialization.JavaScriptSerializer` 报类型找不到，`$ser.Serialize()` 得到空串，随后的请求变成空 body。
- **根因**：没加载 `System.Web.Extensions`，PS 5.1 下不是默认可用。
- **解法**：改用 `ConvertTo-Json`（PS 5.1 会把非 ASCII 转成 `\uXXXX`，仍是合法 JSON，GitHub 正常解析）。
- **如何避免**：本机脚本别假设 .NET 全量类库可用；先 `Get-Command` / `New-Object` 试一次再写进流程。

### 坑：`gh` CLI 没装

- **现象**：`Get-Command gh` 为空，不能用 `gh release create`。
- **根因**：本机只有 git + Git Credential Manager。
- **解法**：从 `git credential fill` 取 GCM 里的 OAuth token（scope `gist, read:org, repo`），走 REST：`POST /releases` → `POST uploads.github.com/.../assets`。
- **如何避免**：不要把 token 写进仓库或长期留在临时目录（本轮 `D:\Temp\ilyayot\tok.txt` 用完即删）。

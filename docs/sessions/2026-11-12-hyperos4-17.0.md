# HyperOS 4 适配：顶栏模糊 / 双搜索栏 / 卡片边距 / 玻璃冻结（2026-11-12）

状态：已完成（OS4 真机验证；OS3 仅代码兼容，未上机）
关联版本：16.8 → 17.0
关联提交：待补（release.ps1 自动提交后回填）

## 1. TL;DR

红米 turbo4pro 升到澎湃 4（OS4.0.2.0.XOLCNXM，Android 17）后，iLayoutSettings 16.8 的四个行为坏掉：顶栏模糊消失、退出搜索出现两个搜索栏、卡片左右边距不跟主题、搜索栏玻璃背景冻结。17.0 逐项修掉；「电池/VPN 被移到隐私组」的排序改动按用户要求整段回退，首页分组保持 16.8。

## 2. 对话重点

- 用户要求（原话要点）：「我的红米 turbo4pro 更新澎湃 4 了，iLayoutSettings 有 bug 了，搜索栏的玻璃会停止在『控制中心』选项，顶栏模糊也没有了，『通用』（关于本机）的卡片在很下面，主界面在点击搜索栏并退出时就会出现两个搜索栏，卡片与屏幕左右两边的边距现在无法使用原来澎湃 3 的主题 theme_values.xml 改了，所以请修复这些内容，并同步 GitHub 和 Releases，版本 17.0，并且澎湃 3 也要适配。」
- 用户提供主题文件 `D:\下载\com.android.settings`（zip，含 `theme_values.xml`）：定义了 `miuix_recyclerview_card_group_margin_start/end=16.5dp`、`miuix_recyclerview_card_group_radius=26dp` 等，并把 `my_device` 改名为「通用」、`other_advanced_settings` 改名为「钱包与 Apple Pay」。
- **决策/否决**：17.0 初版把「电池」「VPN」从网络卡移到隐私卡末尾，让「通用」紧跟「个人热点」。用户在真机上看到后明确否决：「电池和VPN怎么到下面了，不要改布局」。→ 已整段回退，首页分组与 16.8 完全一致；「通用在很下面」按用户要求不做布局改动。
- 范围外但被提到：无。

## 4. 设计思路

- **OS4 适配的核心判断点**：先确认 OS4 的 Settings 里 miuix 类的**字段/方法改名**，而不是猜效果。用 `apktool d` + `baksmali` 解 `Settings-os4.apk`（含 `classes11` 里的 `miuix.nestedheader.widget.NestedHeaderLayout`、`miui…view.MiuiBlurUiHelper`）逐项核对 16.8 的假设：
  - `NestedHeaderLayout.mBlurEffect` → 无，改 `mBlurUiHelper.mBlurRadius`；
  - `mScrollableView` → 无，改 `getScrollableView()`；
  - `HyperMaterialUtils.SUPPORT_HYPER_MATERIAL` → 无，改 `isSupport()` / `mIsSupport`，并新增 `hasMaterialPermission` 门槛。
- **顶栏模糊的两段式方案**：OS3 上「清 clipBounds 就能让内容画到栏下」，OS4 实测清完仍看不到内容 —— 因为 `action_bar_container` 收缩了而列表没动。选择的方案是「列表 translationY 补差」，而不是给列表加 padding 或改 `ActionBarOverlayLayout`：不改 LayoutParams 就不会和 MIUI 的 nested-scroll offset 打架；仅在 SDK≥37 生效，OS3 保持原路径。
- **玻璃冻结为什么选 PixelCopy 而不是修 `root.draw`**：`root.draw` 冻结的根因在硬件层（软件 canvas 拿不到最新显示列表），临时改 `layerType` 会每帧触发重绘、代价更大；PixelCopy 直接读窗口 surface，天然包含滚动后的内容。代价是每帧一次 GPU 读回（区域 1200×236px），用 `pixelCopyInFlight` 防重入、沿用原有 `CAPTURE_INTERVAL_MS` 节流。
- **卡片边距为什么用 hook 而不是改主题**：主题是用户的，模块不该改它；OS4 覆盖发生在 `updateCardGroupMarginForSmallScreen()`，在它之后把主题值写回 `CardItemDecoration` 是最小侵入，且 OS3 上该方法不存在（`hookAllMethods` 软失败），天然不回归。
- **兼容取舍**：所有 OS4 专用路径都加 `Build.VERSION.SDK_INT >= 37` 门控（OS3 = Android 16 = 36），OS3 走 16.8 的老代码。

## 5. 踩过的坑

1. **现象**：OS4 顶栏完全没模糊，连发丝线/透明度也不对。
   **根因**：`ForceBlur.install()` 在 `SUPPORT_HYPER_MATERIAL` 读不到时直接 `return`，后面所有 hook 没装。
   **解法**：`probeSupport()` 三级探测，读不到也继续装；并把 `hasMaterialPermission` 一起强制。
   **避免**：能力探测失败要「保守继续 + 日志」，不要「保守关闭」——ROM 升级最常见的破坏就是字段改名。

2. **现象**：OS4 栏折叠后，栏底(331px)与列表顶(506px)之间留 175px 空白，内容永远进不了栏下。
   **根因**：OS4 把 `action_bar_container` 高度收缩了，但 `NestedHeaderLayout` 没重新布局列表，列表仍按「整栏展开」的高度锚定。
   **解法**：`refreshTopBar()` 里按 `openHeight - barHeight` 对列表 `setTranslationY(-shift)`（仅 SDK≥37）。
   **避免**：OS3 上列表本来就在栏下，同一段代码在 OS3 会二次位移——必须按 SDK 门控，不能只靠「实测这台机器没问题」。

3. **现象**：`root.draw(canvas)` 捕获的玻璃背景冻结，滚动时玻璃里一直是旧内容。
   **根因**：OS4 列表在硬件层里，软件 canvas 的 `draw()` 拿到的是缓存/冻结的显示列表；`backdropChanged()` 因此永远判「没变」。
   **解法**：SDK≥37 用 `PixelCopy` 从窗口 surface 抓当前帧。
   **避免**：诊断时在 `contentDescription` 里输出「捕获次数/变化次数」（`cap=101 chg=1`），一眼看出是捕获问题而不是绘制问题——HyperOS 4 的 logcat 主缓冲区对 shell 不可读，这条通道比日志可靠。

4. **现象**：退出搜索后顶部原生搜索栏常驻，和底部模块栏同时出现。
   **根因**：OS4 在 ActionMode 销毁时把 `mAnchorView` 重新设为 VISIBLE，16.8 只在 install 时设过一次 GONE。
   **解法**：`hideAnchor()` 在 `setBarVisible()` 与每次 global layout（非搜索态）重复隐藏。
   **避免**：ROM 对「隐藏」，UI 元素的恢复时机不可预期，幂等隐藏比「一次性设置」稳。

5. **现象**：主题 `theme_values.xml` 的 16.5dp 卡片边距在 OS4 失效（实测 38px = 12dp）。
   **根因**：OS4 的 `updateCardGroupMarginForSmallScreen()` 用设置自己的 `card_group_margin_horizontal` 覆盖了 miuix 的两侧边距。
   **解法**：hook 该方法后把 `miuix_recyclerview_card_group_margin_start/end` 写回。
   **避免**：主题化 dimension 的生效位置会随 ROM 版本迁移，适配时先 `grep` 新 APK 里同名 dimen 的引用点。


- **双搜索栏**：点底部栏进搜索 → 点 X 退出 → 截图只有一个底部搜索栏（`.tools/shots/v17_exit.png`）。

- **布局回退**：真机截图第一组仍为「飞行模式/无线局域网/蓝牙/蜂窝网络/个人热点/电池/VPN」，第二组「通用/无障碍/操作按钮/待机显示/控制中心…」。

## 7. 未完成 / 下一步 / 风险

- 未完成：
  - OS3 上机回归（顶栏模糊、玻璃 root.draw 路径、卡片边距 hook 不生效是否符合预期）；
  - 「通用在很下面」未修——用户明确要求不要改布局，保留 16.8 顺序；
  - `SearchGlass` 的 PixelCopy 每帧读回在 120Hz 下的功耗/卡顿未量化（`captureCostMs` 日志在本机不可读）。
- 下一步建议：
  1. 有 OS3 设备时装 17.0 回归四项；
  2. 观察 PixelCopy 在长滚动/搜索切换时是否偶发 `pixelcopy:3`（`ERROR_SOURCE_INVALID`，本机出现过，回调里已忽略并保留上一帧）；
  3. 若用户希望「通用」上移，先给两种方案（改分组 vs 只改相邻顺序）让用户看对比图再动。
- 风险：
  - `translationY` 方案依赖 `openHeight`（记录见过的最大栏高）；若某主题把展开态栏高改得和折叠态接近，shift 会偏小，栏下留白重现；
  - `CardMargins` 在没有任何主题覆盖的设备上会把 12dp（`card_group_margin_horizontal`）原样写回，等价于不改；若主题只覆盖了 `card_group_margin_horizontal` 而不覆盖 miuix 那两个 dimen，本 hook 读不到用户期望值；
  - PixelCopy 边界被 `decorView` 裁剪，玻璃贴屏幕底时 backdrop 下方缺一条，边缘 1-2px 可能取到旧内容（当前 `setRenderEffect` 模糊会掩盖）。
